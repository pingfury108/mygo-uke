# mygo-uke · 需求文档

> 一条自录的尤克里里弹唱视频进去，出来一条**带字幕和曲谱**的新视频。
> 配套设计见 `mygo-uke-design.md`。

---

## 1. 一句话需求

上传一段视频 → 自动补全**字幕**和**曲谱** → 导出成可以直接发平台的成片。

「曲谱」不是文档、不是图片，是**画面的一层**：成片里同时有字幕和和弦条。

---

## 2. 背景与动机

| 现状 | 问题 |
|---|---|
| 字幕：剪映「识别歌词」 | 能用，但逐字校对靠手点，视频要过一遍第三方 App |
| 曲谱：找现成谱 / 手抄 | 冷门歌没有；手抄一首 10–15 分钟 |
| 每次发完都有人要谱 | 曲谱是**发布物料**，不是存档草稿 |

**核心痛点不是「不会」，是「每次都要重复做一遍」。**

另有一条硬约束：**不接受 2–4 GB 的 Python 打包分发**。模型必须全部在云端或独立部署的服务里，客户端零模型。

---

## 3. 用户与使用场景

- **单用户**：作者本人（同时也是演奏者，知道歌怎么弹）
- **频率**：一首一发，偶尔一批
- **流程**：录完 → 丢进来 → 校对 1–3 分钟 → 导出 → 上传

---

## 4. 输入 / 输出

### 4.1 输入

| 项 | 规格 |
|---|---|
| 格式 | mp4 / mov（H.264 + AAC） |
| 画幅 | **1080×1920 竖屏**（手机直拍），已是主路径 |
| 内容 | 一个人 + 一把尤克里里，唱 + 扫弦/分解 |
| 时长 | 1–6 分钟（典型 3 分钟） |
| 音质 | 手机直录即可，不需要专业设备 |

### 4.2 输出

| 产物 | 内容 |
|---|---|
| **竖屏 mp4** | 原画 + 字幕 + 顶部和弦条 + 指法图 |
| **横屏 mp4** | 人像居中 + 左侧当前和弦/指法 + 右侧完整谱面 |
| `project.json` | 工程文件，可重开再编辑再导出 |
| `subtitle.srt`（可选） | 备用 |

**判定标准：导出的 mp4 能直接拖进平台上传，不需要二次加工。**

## 5. 画面规格

### 5.1 竖屏 1080×1920

```
┌──────────────────────┐
│                      │ 顶部 4%（平台标题区，留空）
│  ┌──────────────┐    │
│  │ C    G   Am  │    │ 和弦条 y≈6–11%
│  │ ▔▔▔          │ 🎸 │ 当前小节放大+高亮；右侧 96×96 指法图
│  └──────────────┘    │
│                      │
│        人像           │ 视频主体 6%–62%
│                      │
│                      │
│  ┌──────────────┐    │
│  │ 故事的小黄花   │    │ 字幕 y≈78%（可 60–80% 调）
│  └──────────────┘    │
│                      │ 底部 68%–100% 安全区
└──────────────────────┘
```

**硬约束：**

- 右侧 **120px** 让给点赞/评论栏，任何内容不许进
- 底部 **15%** 让给平台文案，字幕不许进（默认落在 78%）
- 和弦条不许压到脸

### 5.2 横屏 1920×1080

人像 606×1080 居中（4:2:0 取偶），左右各 657px：

```
┌───────────────┬──────────────┬───────────────┐
│  当前和弦       │              │  完整弹唱谱     │
│   ┌────┐       │              │  C  G  Am Em  │
│   │指法 │       │    人像       │  故事的小黄花   │
│   └────┘       │   606×1080   │  F  C  Dm G   │
│   C            │              │  童年的荡秋千   │
│                │              │  ▔▔▔ 当前高亮  │
└───────────────┴──────────────┴───────────────┘
```

**竖屏是「刷到就走」，横屏是「跟着练」**——不是降级关系，是两个形态。

### 5.3 曲谱的形态

**只做弹唱卡，不做五线谱 / 简谱 / 六线谱。**

```
[C]  [G]  [Am]  [Em]
故事的小黄花 从出生那年就飘着
```

- 画面里：**字幕负责「词」，曲谱负责「和弦 + 指法」**，两者不重复
- 和弦条只显示「当前 + 接下来 1–2 个」，不是整页谱

### 5.4 只支持尤克里里（硬范围）

**曲谱与指法只做尤克里里一种乐器，不做多乐器抽象。**

| 项 | 规格 |
|---|---|
| 调弦 | **标准调弦 GCEA（high-G）**，不支持用户改调弦 |
| 品数 | 指法图显示 1–5 品；超过 5 品用「7fr / 10fr」标记 |
| 和弦集 | 大三、小三、属七、大七、小七、sus2、sus4、dim、m6、add9，约 80 个 |
| 把位 | 每个和弦存 1–3 个常用按法，按「易弹」排序，默认选最容易的 |
| 变调夹 | 支持 `capo = 0–7`，**同时显示「形状调」和「实际调」** |
| 移调 | P0 只显示原调；移调（P1）后重新选把位 |

**一个容易搞错的点：** `capo = 2` 时谱上写 `C` 的形状，**实际发出的是 D**。所以画面上必须两处都标：

```
原调 D · Capo 2 · 按 C 形状
```

**不可弹和弦的处理：** 曲谱里的和弦名可能不在尤克里里常用集里（如 `Eb7b9`、`C/G`）。

| 情况 | 处理 |
|---|---|
| 有 enharmonic 等价（`D#` ↔ `Eb`） | 直接归一化 |
| Slash 和弦（`C/G`） | 降级为根音和弦，谱面保留小字标注 |
| 扩展和弦不可弹 | 降级到最近的可用和弦（`Cmaj9` → `Cmaj7`），标「近似」 |
| 完全无法映射 | 该小节标红，走待确认流程 |

**不做的事**：吉他 / 钢琴 / 贝斯 / 曼陀林的谱面与指法；调弦切换；指弹六线谱；和弦编配。

## 6. 功能需求

### P0（第一版必须有）

| ID | 功能 | 说明 |
|---|---|---|
| F1 | 导入视频 | 拖入视频，读取时长 |
| F2 | 语音转写 | 火山豆包流式 ASR，**句级**时间戳 |
| F3 | 曲谱导入 | 图片/文本曲谱，拿 `chords / key / capo / BPM / 拍号` |
| F4 | 小节化 | 有 BPM 时按拍号切分；否则按和弦变化点生成 `bars` |
| F5 | 校对台 | 改字幕文字、拖句起止、点选替换和弦、选节奏型 |
| F6 | 预览 | 播放头拖动，预览画布实时反映字幕+和弦+指法 |
| F7 | 导出竖屏 | 字幕+和弦条烧进画面，输出 1080×1920 mp4 |
| F8 | 工程保存 | `project.json` 落盘，重开能续 |

### P1

| ID | 功能 |
|---|---|
| F9 | 导出横屏 1920×1080（人像 + 左右面板） |
| F10 | 导出 SRT |
| F11 | 样式预设（字号/颜色/主题） |

### P2（不做也行）

| ID | 功能 | 备注 |
|---|---|---|
| F12 | 批量处理 | 目录级一次跑一批 |
| F13 | 曲库索引 | 歌名/调/和弦/标签可检索 |
| F14 | 字级卡拉OK 逐字高亮 | 依赖 ASR 字级时间戳 |

---

## 7. 非目标（明确不做）

这一节和功能清单同等重要，防止范围膨胀：

1. ❌ **节奏型自动识别**——扫弦 pattern 从音频反推没有可行方法，用**模板手选**
2. ❌ **五线谱 / 简谱 / 指弹六线谱**
3. ❌ **字级字幕**（P0 阶段）——句级足够
4. ❌ **本地模型 / 离线能力**——零模型是分发前提
5. ❌ **Web UI / 内嵌浏览器**——客户端是 MyGo 原生 App
6. ❌ **多用户 / 云同步 / 账号体系**
7. ❌ **DRM 相关**、任何版权绕过
8. ❌ **旋律提取、扒带、自动编配**
9. ❌ **吉他 / 钢琴 / 贝斯等其他乐器的谱面与指法**——只做尤克里里（见 §5.4）
10. ❌ **调弦切换**（low-G、D 调弦、Baritone）——固定标准调弦 GCEA
11. ❌ **多乐器抽象层**——不做 `instrument` 接口，代码里直接写死尤克里里

---

## 8. 非功能需求

| 项 | 指标 |
|---|---|
| 分发体积 | **≤ 100 MB**（不含用户视频） |
| 导出耗时 | 3 分钟视频 ≤ **8 分钟**（含分析 + 合成） |
| 单帧渲染预算 | ≤ **40 ms**（1080×1920） |
| 分析等待 | 上传 + 分析 ≤ **90 秒** |
| 平台 | macOS（Apple Silicon）优先；Windows 次之；Linux 不做 |
| 字体 | **必须内嵌**（思源黑体子集），不依赖系统 |
| 隐私 | 视频不出本机；只上传压缩后的音频（可选人声分离轨） |
| 稳定性 | 断网/API 失败要有明确报错，不能静默卡住 |

---

## 9. 验收标准

1. **三首歌**跑通：从拖入到导出成品，**人工修改时间 < 手工抄谱时间**（10–15 分钟）
2. 导出的竖屏 mp4 能**直接上传**抖音 / 小红书 / 视频号，不需要二次加工
3. 导出的横屏 mp4 能直接上传 B 站 / YouTube
4. 和弦准确率（人耳核对）**≥ 80%**，错的地方能一眼看出来并在 UI 里改掉
5. 装包体积 ≤ 100 MB，双击即用，不需要装 Python / ffmpeg
6. **指法图正确**：每个和弦的按法在真琴上按得响、按得住；`capo > 0` 时「形状调 / 实际调」两处都对
7. 表外和弦（`Bb`、`Eb` 这类 barre 和弦）有明确的可弹提示，不出现「画得出来但弹不了」的图

## 10. 里程碑

| 阶段 | 内容 | 产出 |
|---|---|---|
| **M0** | 三个可行性验证（见设计文档 §8） | 结论：方案成立/要改 |
| **M1** | 骨架 + 管线（视频+曲谱→ASR→对齐→bars） | `project.json` 能生成 |
| **M2** | 校对台（播放头联动 + 编辑） | 能改、能看 |
| **M3** | 合成导出（竖屏） | 能出片 |
| **M4** | 横屏、SRT、样式 | P1 完成 |

**M0 不过就不进 M1。**
